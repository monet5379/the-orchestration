## 버전 규칙 (0.1.x)

**내부는 잘게, 외부는 배포 때 한 장으로 묶는다.**  
올릴 때 파일·체크리스트: [`../VERSION.md`](../VERSION.md)

1. **내부**  
   - 작업 단위마다 `0.1.xx.md`를 새로 만든다 (`0.1.31` → `0.1.32` → …).  
   - 이미 공유·확정된 과거 스냅샷(예: `0.1.30`) 위에 이후 작업을 덮어쓰지 않는다.  
   - 플레이어 체감이 없어도(리팩터·구조) 내부 노트는 남긴다. 그 경우「외부 후보: 없음」.

2. **외부**  
   - 배포할 때만 `../external/0.1.yy.md`를 작성한다.  
   - `yy`는 **그 배포에 포함하는 내부 최신(또는 배포에 붙인) 마이너**로 맞춘다.  
   - 본문은 **직전 외부 공유본** 대비 플레이어가 느낄 변화만 모은다 (중간 내부 31·32…를 나열하지 않아도 됨).  
   - 체감 없는 내부 버전은 외부에 넣지 않거나 한 줄로만 언급한다.

3. **제품 표시** (`index.html` / `main.js?v=` / console)  
   - **외부 배포 시** 외부 버전과 맞춘다. 상세 목록은 [`../VERSION.md`](../VERSION.md) **B**.  
   - 내부만 올린 동안에는 잠시 이전 공유 번호여도 된다. 내부 노트에「제품 표시는 배포 시 맞춤」을 적는다.

4. **메이저(0.2.0 등)**  
   - 기본은 위 0.1.x 흐름을 유지한다.  
   - 공유 단위가 크게 바뀔 때(예: 기획자 시트 연동이 배포의 핵심)만 별도로 0.2.0을 검토한다.

커밋 메시지 규칙은 [`../../COMMIT.md`](../../COMMIT.md). 제목에 버전 접두어는 쓰지 않는다.
