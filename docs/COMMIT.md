# 커밋 메시지 규칙

이 프로젝트는 [Conventional Commits](https://www.conventionalcommits.org/)를 따르고, **제목·본문은 한글로** 작성합니다.

과거 영어 커밋은 그대로 둡니다. **지금부터** 아래 형식을 사용합니다.

---

## 형식

```text
<type>(<scope>): <제목>

[본문 — 선택]

[Footer — 선택]
```

- 제목 줄은 **72자 이내**를 권장합니다.
- `scope`는 선택입니다. 변경 영역이 분명할 때만 붙입니다.
- 본문은 필요할 때만 씁니다. **왜** 바꿨는지를 1–2문장으로 적습니다.

---

## Type

| type | 언제 쓰나 |
|------|-----------|
| `feat` | 사용자에게 보이는 기능·플레이 규칙 추가 |
| `fix` | 버그 수정 |
| `docs` | 문서만 변경 (패치노트, README, 설계 문서 등) |
| `style` | 동작 변화 없는 포맷·들여쓰기·이름만의 정리 |
| `refactor` | 동작은 같지만 구조·가독성 개선 |
| `perf` | 성능 개선 |
| `test` | 테스트 추가·수정 |
| `chore` | 빌드·런처·설정·잡무 (기능 변경 아님) |

한 커밋에 성격이 섞이면 **주된 의도**의 type 하나를 고릅니다.  
예: 기능 추가 + 문서 갱신이면 `feat`, 문서만이면 `docs`.

---

## Scope

디렉터리·영역 기준으로 짧게 씁니다.

| scope | 대상 |
|-------|------|
| `prototype` | `prototype/` 전반 |
| `ui` | 화면·타이머·버튼 등 UI |
| `ai` | 상대 AI |
| `launcher` | `serve.py`, `run.bat`, `run.ps1` 등 실행 환경 |
| `docs` | `docs/`, 루트 README 등 |
| `ci` | GitHub Actions 등 |

애매하면 scope를 생략해도 됩니다.

```text
fix: SELECT 진입 시 페이즈 혼선 수정
```

---

## 제목 (한글)

- **무엇을/왜**가 한 줄로 드러나게 씁니다.
- 명령형·간결한 서술형 모두 허용합니다.  
  예: `…을 추가`, `…을 수정`, `…을 단축`
- 문장 끝에 마침표를 붙이지 않습니다.
- 제목에 `v0.1.30:` 같은 **버전 접두어는 쓰지 않습니다.**  
  버전은 패치노트·본문·태그로 표현합니다.

---

## 본문 (선택)

제목만으로 이유가 안 드러날 때 씁니다.

- **why** 중심 (파일 나열·diff 요약은 피함)
- 빈 줄로 제목과 본문을 구분
- Breaking change가 있으면 본문 또는 footer에 `BREAKING CHANGE:`로 명시

---

## 예시

```text
feat(ui): ADJUST 제한 시간을 15초로 단축

양측이 선택을 마치면 남은 타이머를 끊고 즉시 RESOLVE로 진행한다.
```

```text
fix(launcher): Ctrl+C 시 서버가 종료되도록 run.bat 수정

백그라운드 프로세스가 남지 않도록 포그라운드에서 실행한다.
```

```text
docs: 0.1.30 패치노트와 프로토타입 구조 문서 갱신
```

```text
chore(launcher): serve.py에서 JS에 no-store 캐시 헤더 적용

모듈 캐시 불일치로 부팅이 깨지는 경우를 줄인다.
```

```text
refactor(ai): 상대 조정·허세 결정을 한 계획으로 통합
```

## 버전·패치노트와의 관계

- 정책: [`patch-note/internal/README.md`](./patch-note/internal/README.md)  
- **올릴 때 체크리스트:** [`patch-note/VERSION.md`](./patch-note/VERSION.md)

- **내부** (프로그래머): 의미 있는 변경마다 `docs/patch-note/internal/0.1.xx.md`를 **새로** 작성합니다. 이미 공유된 버전에 이후 작업을 덮어쓰지 않습니다.
- **외부** (공유): **배포 시에만** `docs/patch-note/external/0.1.yy.md`를 씁니다. 본문은 **직전 외부 공유본** 대비 플레이어 체감만 모읍니다.
- 제품 표시 버전은 **외부 배포 시** 맞춥니다. 내부만 올린 동안에는 이전 공유 번호여도 됩니다.
- 커밋 제목에 버전을 넣지 않아도 됩니다.
- 한 외부 릴리스에 내부 버전·커밋이 여러 개여도 됩니다.

---

## 하지 않을 것

- `update`, `수정`, `워킹`처럼 내용이 없는 제목
- 영어로만 된 제목·본문 (이 규칙 적용 이후)
- 한 커밋에 서로 무관한 대형 변경을 섞기 (가능하면 나눔)
